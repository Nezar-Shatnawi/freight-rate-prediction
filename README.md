# Freight Rate Prediction Challenge

Reproducible CatBoost solution with chronological validation, final predictions,
the **unmodified supplied scorer**, and a DOCX report.

## Submission files

- `validation_predictions.csv`: exactly 12,000 `load_id,predicted_rate` rows.
- `data/december_chart_inputs.csv`: all 31 fixed December rows, with predictions.
- `december_predictions.csv`: convenient duplicate of that completed chart input.
- `scorer_results/candidate_december.png`: generated by the supplied `score.py`.
- `freight_rate_report.docx`: split, validation results, data-quality treatment,
  model rationale, limitations, and the scorer-generated December chart.
- `loom_walkthrough.md`: timed 2–3 minute recording script.

**The Loom video has not been recorded.** Record your screen/voice using the
script and submit the actual share link. A script is not a replacement for it.

## Setup

Python 3.11+ recommended; the recorded run used Python 3.13.11.

```bash
git clone https://github.com/Nezar-Shatnawi/freight-rate-prediction.git
cd freight-rate-prediction
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

`requirements.txt` contains the supplied scorer requirements plus CatBoost,
scikit-learn, and python-docx. `requirements-lock.txt` records the exact versions
of the execution environment; use it instead for an exact dependency replay.

Raw assessment datasets are intentionally **not** published in this public
repository. Obtain them from the assessment and place/rename them as:

```text
data/train_test.csv
data/validation.csv
data/validation_predictions_template.csv
data/december_chart_inputs.csv
```

The completed December file is already included in this repository; its
`predicted_rate` values are overwritten on a new run. No GitHub credentials or
other secrets are needed to train locally.

## Reproduce

```bash
python train.py
python score.py --predictions validation_predictions.csv --december-predictions data/december_chart_inputs.csv
python test_solution.py
python make_report.py
```

Training compares seven candidates and a median-rate/mile baseline, performs
the locked temporal test, refits the selected models on all labeled rows,
then writes both final prediction files. A run takes a few minutes on CPU.

For an existing checkout containing prediction files, the scorer can run
without any raw datasets:

```bash
python score.py --predictions validation_predictions.csv --december-predictions data/december_chart_inputs.csv
```

## Validation design

| Partition | Dates | Rows | Purpose |
|---|---|---:|---|
| Training | Jan–Jul 2025 | 33,718 | Fit candidate models |
| Tuning | Aug 2025 | 4,759 | Early stopping and model selection |
| Locked test | Sep–Oct 2025 | 9,523 | Untouched future-month evaluation |
| Final prediction | Nov–Dec 2025 | 12,000 | No labels available |

The predeclared selection criterion is **August dollar MAE**. The selected tree
count is fixed before fitting on January–August and evaluating the locked test.
September–October is not used to switch models or tune hyperparameters.
Only after that evaluation is the final model refit on January–October.

The supplied scorer checks the submission contract and draws the chart. It
**does not measure prediction accuracy**: the organizer computes the hidden
final score after submission. Internal MAE, RMSE, R² and MAPE are in
`artifacts/metrics.csv` and the report.

### Locked September–October results

| Model | MAE ($) | RMSE ($) | R² | MAPE |
|---|---:|---:|---:|---:|
| Median-rate/mile baseline | 256.95 | 684.25 | 0.7990 | 11.63% |
| Selected main model | 117.41 | 636.91 | 0.8258 | 5.04% |
| Reduced-schema chart model | 107.59 | 633.55 | 0.8276 | 4.75% |

The main model is `core_rpm_mae` (292 trees); the chart model is
`chart_rpm_mae` (707 trees). Both were selected on August, before seeing these
locked-test results. The chart model's better locked-test MAE did not trigger
a post-hoc replacement of the already selected main model. The higher RMSE
relative to MAE reflects large errors on a small number of unusual loads.

## Modeling choices

- Nonpositive weights are treated as missing and flagged; missing numeric values
  use an explicit sentinel. IDs are never predictive features.
- Targets are retained, including unusual high-rate loads. No validation
  outliers are removed from metrics.
- Quote-signal correlation changes sign across months, so inclusion/exclusion
  is tested explicitly on future-month tuning data.
- CatBoost models categorical lanes/equipment and continuous distance, weight,
  market, calendar and geographic features.
- Models compare MAE/RMSE loss and total-rate/rate-per-mile targets.
- The December chart has fewer fields than the main validation data. A separate,
  temporally validated reduced-schema model predicts it without inventing
  absent market indices, quotes or coordinates.
- Predictions are joined to the template by `load_id`, not row position.

- `test_solution.py`: five structural/feature-contract tests.
- `make_report.py`: DOCX report and Loom script from actual run artifacts.
- `artifacts/audit.json`: quality checks and monthly quote correlations.
- `artifacts/results.json`: selected configuration, metrics, feature importances.
- `artifacts/metrics.csv`: tuning and locked-test results.
- `artifacts/scorer_output.txt`: scorer execution log.
- `artifacts/environment.json`: Python/dependency versions and input checksums.

Models and row-level internal test results are generated locally, not published.
The downloadable private submission bundle also includes the supplied data
and fitted models, making local replay convenient.

## Limitations

There are only ten months from one year. Winter/holiday behavior is not
identified reliably; tree models cannot reliably extrapolate beyond observed
numeric ranges. Eight prediction cities are unseen during development.
The temporal test does not quantify performance on unseen cities or actual
November–December labels. More historical years, rolling-origin validation,
a geographic holdout and verification of quote-signal provenance are the next
steps. Feature importance is not a causal explanation.
